# Test map - Task tags (backend)

Every row is runnable on its own. Copy the command. One map for the whole task-tags requirement in this repo: the tag-library unit (FEAT-TAG-01) owns the first block; later backend units add their rows below it. The `-t` filter is a regex, so each command names the leading words of the test, cut before any character that would change the match. Contract-tier rows are the 401 envelope checks, which need no database; the success and refusal shapes are asserted against zod schemas inside the integration rows. TS-n is the scenario number in the feature's test-scenarios.md. Concurrency-tier rows run under the integration project (QG-007); no separate concurrency project exists yet, so a dedicated gate for them (QG-013) is a follow-up for /qa:setup. The post-delete sweep of task links (DEC-290) is covered only by the existing delete tests, which cover the first pull; no test interleaves a task write with a delete. Rows marked (supporting) are cheap unit checks of a constant or an index declaration; they back a behaviour row and do not prove it alone.
